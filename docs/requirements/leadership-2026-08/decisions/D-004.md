## Decision details

**Question:** How should Code Vault cryptotext be retained, and what is the encryption key rotation schedule?

**Selected option:** Versioned authenticated envelope, 5-year retention after terminal lifecycle, legal-hold suspension, 90-day active key rotation, and historic decrypt-only key versions.

**Approver name:** [Delegated Project Owner]
**Approver role:** Project Owner (delegated authority from leadership review)

**Approval date:** 2026-08-22

**Authoritative source/version:** MarkFlow_delegated_decision_records_and_prompts.md, decision table, dated 2026-08-22

**Affected MF-REQ IDs:** MF-REQ-060, MF-REQ-061, MF-REQ-062, MF-REQ-063, MF-REQ-064

**Implementation authorization scope:** W0-03a KMS adapter, envelope encryption, key rotation metadata

### Policy

1. Code Vault uses a **versioned authenticated envelope** (magic prefix, format version, key version, ciphertext).
2. **5-year retention after terminal lifecycle** (COMPLETED/EXPIRED/WITHDRAWN/WRITTEN_OFF). This is a product-policy starting value, not asserted law.
3. **Legal-hold suspension** prevents deletion of codes under active legal hold.
4. **90-day active key rotation**: encryption keys rotate every 90 days; old key versions retained for decryption only.
5. **Historic decrypt-only key versions**: old keys are retained but cannot encrypt new data.
6. No production data exists yet; these policies apply when production data first appears.

### Test/acceptance evidence required
- [ ] Envelope format includes magic prefix, format version, key version, ciphertext length
- [ ] Decrypt succeeds with current key version
- [ ] Decrypt succeeds with rotated key version (key versions retained)
- [ ] Legal-hold flag prevents deletion of codes under hold
- [ ] 5-year retention policy configurable and testable
