## Decision details

**Question:** Should MarkFlow have write authority to IS MPT Stage, and under what conditions?

**Selected option:** MPT business-write authority is denied for this phase. Read-only Stage discovery only after W0-03a acceptance.

**Approver name:** [Delegated Project Owner]
**Approver role:** Project Owner (delegated authority from leadership review)

**Approval date:** 2026-08-22

**Authoritative source/version:** MarkFlow_delegated_decision_records_and_prompts.md, decision table, dated 2026-08-22

**Affected MF-REQ IDs:** MF-REF-100, MF-REF-101, MF-REF-102, MF-REF-103, MF-REF-104, MF-REF-105

**Implementation authorization scope:** W0-03a adapter foundation (read-only); W0-03c MPT contract verification (read-only); W0-04 durable processing

### Policy

1. MPT adapter may perform **only explicitly allow-listed read-only Stage discovery** after W0-03a acceptance.
2. **Authentication transport is not an authorization to perform business writes.** Having valid MPT credentials does not grant write permission.
3. `createOrder`, utilisation, and document submission **remain disabled** for this phase.
4. Any future write authority requires a separate decision record with legal/finance/integration ratification.

### Test/acceptance evidence required
- [ ] MPT adapter tests pass with read-only operations only
- [ ] No POST/createOrder calls to Stage in any code path
- [ ] No submitUtilisation calls to Stage
- [ ] No document submission calls to Stage
- [ ] Authentication works but write permission is denied
