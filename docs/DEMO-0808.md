# DEMO 08.08 — сценарий показа учредителям

**Подготовка (до показа):**

```bash
npm install
npm run demo:reset          # свежая dev.db + seed (админ admin@demo / demo-password)
npm run dev                 # API на :3000  (запускать с MFA_ENABLED=true для demo-smoke, см. ниже)
# в другом терминале:
npm run dev --workspace @markflow/web   # web на :5173
```

**demo-smoke** требует сервер с `MFA_ENABLED=true` (проверяет MFA-негатив 403 + happy-path: /api/products не требует роли/MFA, поэтому все чек-поинты проходят). Запуск сервера:

```bash
# Windows PowerShell
$env:MFA_ENABLED="true"; $env:JWT_SECRET="dev-secret"; npm run dev
```

**Проверка перед показом (авто):**

```bash
npm run demo:smoke          # E2E-путёвка по живому API, все PASS
```

## Клики (сквозной путь)

| Шаг | Клик                                                                                                                  | Что видит учредитель                                                                                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `/apply`                                                                                                              | форма «Заявка на подключение» (7 реквизитов + согласие v1)                                                                                    |
| 2   | Заполнить БИН (напр. `123456789042`), остальное — произвольно, отметить «Согласен с офертой (v1)», «Отправить заявку» | **201** — тост «Заявка отправлена. Статус: PENDING»; ссылка «Проверить статус»                                                                |
| 3   | Повторить «Отправить заявку» тем же БИН                                                                               | кнопка отключена, тост «Заявка уже существует. Статус: PENDING» (дубль БИН — AT-02)                                                           |
| 4   | (оператор, отдельный терминал) — curl одобрения, см. ниже                                                             | после одобрения: `/status?id=...` → «Статус: Одобрена», ссылка «Перейти ко входу»                                                             |
| 5   | `/login` (admin@demo / demo-password ИЛИ логин заявителя после одобрения)                                             | вход → `/products`                                                                                                                            |
| 6   | `/products` → «Загрузить инвойс (демо)»                                                                               | **38 красных строк** (ТНВЭД 27101919, вне перечня) + **2 зелёные** (2710198200, 3403191000 — demo); подсказка «возможно 2710198200» у красных |

**Готовый curl оператора (одобрение вживую):**

```bash
# подставь реальный id из ответа POST /onboarding/applications
curl -s -X POST http://localhost:3000/operator/approvals/<APP_ID> \
  -H "Content-Type: application/json" -H "Accept: */*" \
```

## Речь (3 минуты)

1. **Проблема:** маркировка моторных масел в РК — обязательна (приказ №44-н/қ от 30.01.2026). Вручную — десятки атрибутов, риск ошибок, штрафы.
2. **Инвойс — недоверенный черновик (ADR-019):** загружаем инвойс → видим 38 позиций. Большинство — ТНВЭД **27101919**, который ВНЕ перечня маркировки → подсвечены **красным**, с подсказкой «возможно 2710198200» (как исправить). 2 demo-позиции из перечня — **зелёные**.
3. **Путь:** заявка → оператор одобряет → tenant+счёт+роли атомарно → вход → товары. Всё на одном стеке (NestJS+Prisma+SQLite в прототипе, прод — PostgreSQL/MinIO/RabbitMQ на сервере).
4. **Что дальше:** карточка 44 атрибута (валидируемый источник), заказ КМ через симулятор ИС МПТ, этикетка+скан.

## Заметки

- **«Сессия истекла — перелогиньтесь вручную»**: JWT живёт 1 час; истечение → тост 401. Авторедирект на /login — не в прототипе (LOW из review-t2.md), просто кликните «Вход» снова.
- **Если заявитель не логинится** после одобрения (нет пользователя у заявителя — provisioning создаёт только admin@<bin>) — используйте **seeded-админа** `admin@demo / demo-password`.

## FALLBACK (если живой путь заявки/одобрения падает)

1. `npm run demo:reset` (свежая dev.db — гарантированно известное состояние).
2. Логин **seeded-админом**: `/login` → `admin@demo` / `demo-password` → `/products`.
3. «Загрузить инвойс (демо)» → 38 красных + 2 зелёных, подсказка.
4. **Устный рассказ**: провести по пути «заявка → одобрение → вход» словами, показать curl оператора, объяснить, что цепочка кодов (заказ КМ) — в следующем цикле. **Цепочку кодов НЕ берём** (контрольная точка 12:00).
