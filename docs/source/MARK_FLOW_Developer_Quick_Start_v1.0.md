**MARK FLOW — Developer Quick Start**

Краткое руководство разработчика по архитектуре, сущностям и правилам реализации.

# 1\. Что строим

MARK FLOW — много-модульная система управления маркировкой и прослеживаемостью. Пользователь работает в 16 разделах, но данные и процессы должны оставаться сквозными: один и тот же товар, код, поставка, документ или задача не дублируются между модулями.

| ----- | ------------------------- | ------- |
| 1     | Главная                   | HOME    |
| 2     | Центр задач и уведомлений | TASK    |
| 3     | Глобальный поиск          | SEARCH  |
| 4     | Каталог товаров           | CAT     |
| 5     | Заказ кодов               | ORD     |
| 6     | Печать и этикетки         | PRINT   |
| 7     | Агрегация                 | AGG     |
| 8     | Операции и документы      | OPS     |
| 9     | Поставки                  | SHP     |
| 10    | Производство              | PRD     |

| 16    | Настройки                 | SET     |

# 2\. Главные правила разработки

- Backend — источник истины для прав, валидаций и state transitions.
- Большие таблицы и массовые действия — только server-side.
- Необратимые действия — подтверждение + audit + idempotency.
- Длительные действия — BackgroundJob + Центр задач/уведомлений.
- Внешние интеграции — через Integration Gateway, а не напрямую из UI.
- ИИ не получает дополнительных прав и не обходит подтверждения.
- Любой объект открывается из Глобального поиска и имеет историю/связанные объекты, где применимо.

# 6\. Унифицированный шаблон экрана

1. GET list/detail → RBAC + tenant scope → DTO.
2. Изменение → backend validation → command → transaction/outbox → audit → response/job.
3. Внешний вызов → Integration Gateway → idempotency/retry → mapping → domain status.
4. Ошибка → error envelope → при необходимости Task/Notification.
5. Массовая операция → selection query snapshot → BackgroundJob → per-item result → итог/файл ошибок.

# 7\. Минимальный Definition of Done

- UI по мокапу
- API-контракт
- валидация backend
- RBAC
- аудит
- ошибки
- телеметрия
- тесты
- обработка повторов/таймаутов
- документация endpoint/state transition

# 8\. Что нельзя додумывать без Product/Integration решения

- Финальные API-контракты и ограничения GS1, НКТ, ИС МПТ, 1С/ERP, ЭСФ и таможенных интеграций.
- Точные нормативные state transitions для каждой товарной группы и типа операции.
- Полный перечень обязательных атрибутов карточек по товарным группам.
- Правила тарификации и источник финансовой истины для Биллинга.
- Целевые SLA, RPO/RTO, retention аудита и бизнес-данных.
- Ограничения по объёму заказов/операций, если они задаются внешними системами.
- Финальная матрица ролей/permissions и схема согласований.
- Форматы печати, поддерживаемые принтеры/драйверы и протокол агента печати.
- Модель offline ТСД и допустимый период автономной работы.
- Политика использования ИИ, модели, хранение диалогов и разрешённые инструменты.
