# INTEGRATIONS.md — карта интеграций MarkFlow

Карта интеграций продукта: **close** (договорные, вне API-площадки) vs **open API**
(государственные/отраслевые с публичной спецификацией), по рынкам KZ/РФ и
типам данных. Основа — доска интеграций + ADR-005 (порты) + волны ROADMAP.

## Модель портов (ADR-005)

Вся интеграция — через порты/адаптеры (`apps/api/src/integrations.ts`,
`ecom.adapter.ts`, `files.controller.ts`, `kms.adapter.ts`). Выбор реализации:
`adapters.<system>=mock|http` (config/env). Мок реализует тот же интерфейс и
используется в контрактных тестах (симулятор ИС МПТ — `MockMptAdapter`).

Транспорт MVP: файлы (1С) + JSON-эндпоинты; XML-обмены — с интегратором (октябрь).

| ----------------------- | ------------------ | ----- | ------------------------------------------------------- | --------- | ------------------------------------------------------------ |
| **ИС МПТ / xTrace**     | open API           | KZ    | КМ: заказы, коды, ввоз/вывод                            | симулятор | `docs/CONTRACT-IS-MPT.md`; `IMptAdapter`; волна 1            |
| **НКТ (NTIN)**          | open API (договор) | KZ    | Регистрация карточек → NTIN                             | мок       | `INktAdapter` (submit/getStatus, SLA)                        |

| **1ecom**               | close              | KZ    | Контрагент (BIN), товары                                | мок       | `IEcomAdapter`; ручной режим оператора (ADR-004); волна 3    |
| **1С (файлы/ДТ)**       | close, файлы       | KZ    | Бухгалтерия: PaymentImport, ServiceAct, MovementJournal | файлы v1  | ADR-010; `POST /1c/export`; 1С — система записи, не MarkFlow |

## KZ vs РФ

- **KZ (MVP-1)**: ИС МПТ, НКТ, GS1, 1ecom, 1С, MarkMobile, ЭДО.
- **РФ (эволюция)**: Гис МТ / МДЛП / АТК — отдельная волна, до неё не дойдём
  в MVP; структура кода (порты) позволяет добавить РФ-контур без переделки.

## ТД (товарные документы) = документы клиента, не API

**ТД — это документы клиента** (инвойс + ДТ), передаваемые как файлы/реквизиты,
**не отдельный API**. В MVP:

- Инвойс → `POST /products/drafts/import` (rows) → DraftProposal (source invoice).
- ДТ → мастер «Оформить ввоз» (`POST /import`): orderId + customsDeclaration
  {date, number, authorityCode}. Несколько ДТ на один заказ и подмножество кодов —
  тикет **W5-03** (post-demo).

## Связь с ROADMAP (волны)

1. **Сен**: ИС МПТ real (`adapters.mpt=http`, контрактные тесты, замер лимитов на STAGE).
2. **Окт**: GS1, НКТ, 1С боевой транспорт, банк/выписки.
3. **Ноя**: 1ecom по договору, ЭДО/ЭСФ.
4. **Дек–янв**: UAT (AT-01…18), нагрузка 150%, hardening, PROD (01.02.2027 — оборот).

## Безопасность и аудит интеграций

- Полные КМ наружу (1С/export/печать) — только с аудитом **CV-032** (VaultExport).
- КМ в 1С не уходят: MovementJournal с `kmHash` (SHA-256 канонической raw-строки ADR-006).
- Криптохвост (ai91/ai92) — envelope AES-256-GCM, маска в UI/логах.
