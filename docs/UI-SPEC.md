# UI-SPEC — спецификация фронт-пересборки MarkFlow v4

**Источник:** `docs/ui-reference.html` — интерактивный продуктовый прототип v4.0 (131KB, 23 страницы, 5 ролей).
**Дата:** 2026-08-11
**Назначение:** единый visual contract для пересборки `apps/web` (React+Vite+EntityList, ADR-008). Фронт пересобирается ПОСЛЕ ревью этой спеки пользователем.

---

## 1. Принципы

1. **Спека = visual contract.** Каждый экран прототипа = эталон. Отклонение возможно только через Change Request (ТЗ §17.3).
2. **EntityList (ADR-008)** — один data-driven компонент для таблиц; экран = конфиг, не отдельная страница.
3. **Роли** — прототип имеет 5 ролевых пространств (см. §3); фронт показывает/скрывает навигацию по роли из JWT (`roles[]`, тикет T0-RBAC).
4. **Командная палитра (Ctrl+K)** и **глобальный поиск** — обязательны (прототип: ⌘-кнопка, поиск в topbar).
5. **Дизайн-система** — строго по CSS-токенам прототипа (ниже, §2).
6. **Данные** — реальные backend-эндпоинты; демо-заглушки (как в прототипе) допустимы только на этапе переноса, затем заменяются на API.

## 3. Навигация и роли

### 3.1 Навигация (sidebar)

**Рабочее пространство:** Главная, Информация о коде
**Основные процессы:** Товары(148), Заказы кодов(7), Code Vault, Этикетки, Операции, Склад и ТСД, Документы(4)
**Управление работой:** Задачи(12), Производство, Контрагенты, Конструктор процессов
**Контроль и сервис:** Центр исключений(7), Состояние системы, Отчёты, Биллинг, Интеграции, Поддержка(2)
**Снизу:** Организация и доступ, Кабинет оператора, Журнал аудита

### 3.2 Роли (role-switch в topbar)

| Роль        | Прототип-профиль      | Ориентация               |
| ----------- | --------------------- | ------------------------ |
| `admin`     | Администратор клиента | все рабочие пространства |
| `operator`  | Оператор маркировки   | Операции                 |
| `warehouse` | Складской оператор    | Склад и ТСД              |
| `manager`   | Руководитель          | Главная                  |
| `platform`  | Оператор платформы    | Кабинет оператора        |

Фронт: при login получает `roles[]` (тикет T0-RBAC) → выбирает дефолтную страницу и набор nav-item.

### 3.3 Topbar

- breadcrumb (`MarkFlow / <страница>`)
- глобальный поиск (товар, GTIN, код, документ, операция)
- role-switch (select)
- ⌘ (command palette), ⚠ (exceptions), 🔔 (notifications drawer), профиль (avatar + имя + роль)

## 4. Экраны (23) — контракт

### 4.1 Login (страница входа)

- 2 колонки: hero (градиент navy, 4 feature-points, бренд) + форма.
- Поля: Логин, Пароль, «Запомнить меня», кнопки «Войти» (primary) и «Войти с ЭЦП» (light).
- Демо-креды в прототипе: `demo@markflow.kz` / `MarkFlow2026` — **заменить** на реальные `admin@demo`/`demo-password` (seed).
- После login → hash `#dashboard`, старт tour (если не показан).

### 4.2 Dashboard (Главная)

- Page-actions: «↻ Обновить», «+ Заказать коды» (→ orders wizard).
- **Quickbar** (6 quick-actions): Создать товар, Заказать коды, Запустить задание, Сканировать, Подписать, Все действия.
- **KPI (5)**: карточки 148, 2,46 млн кодов, 184 500 печать/7д, 96 720 операций/мес, 485 450 ₸ баланс.
- **Сквозной процесс** (7 шагов): Товар ✓ → GTIN/НТИН ✓ → Заказ кодов (active) → Этикетка → Печать → Нанесение → Оборот.
- **Динамика операций** (chart SVG 2 линии) + **Требует внимания** (notice/error-box + кнопка «Открыть центр исключений»).
- **Последние события** (timeline) + **Распределение кодов** (donut + legend).

**Backend:** `GET /dashboard/summary` (5 счётчиков, Q10) + события (не в API — mock/эволюция) + баланс (`GET /billing/...`).

### 4.3 Code Check (Информация о коде)

- Поиск Data Matrix/GTIN/serial + кнопки «📷 Камера», «▶ Начать сканирование».
- Scan-пустое состояние → результат: badge «В обороте», товар/GTIN/serial/владелец/место/упаковка (info-grid), кнопки «Скачать историю», «Выполнить действие».
- Timeline истории жизненного цикла (6 событий, цвета по статусам).

**Backend:** `GET /codes/:codeKey` (есть `GET /codes/:orderId/codes` — нужен lookup по коду) + `CodeEvent` история.

### 4.4 Products (Каталог товаров)

- Page-actions: «⇩ Шаблон импорта», «⇧ Импорт», «+ Создать товар».
- Toolbar: поиск, группа, статус, «⚙ Колонки», «Сохранить вид».
- Таблица: чекбоксы, Товар(фото+имя+link), GTIN/НТИН, Группа, Статус(badge), Упаковки, Коды, Обновлено, ⋮.
- Пагинация «1–8 из 148».

**Backend:** `GET /products/cards` + `GET /products/drafts` (по ADR-022/023), статусы по moderation.

### 4.5 Product Detail (Карточка товара)

- Header: фото, имя, badge статуса, GTIN·НТИН·SKU, badge группы/упаковки/версии, владелец.
- Actions: «Дублировать», «Отправить на модерацию», «Редактировать».
- Tabs: Основная информация / Юниты и упаковки / Коды / Этикетки / История и версии.
- Основная: идентификация, классификация (info-grid).

**Backend:** `GET /products/cards/:id` (существует) + модерация (`POST /products/cards/:id/submit`).

### 4.6 Orders (Заказы кодов)

- KPI-4: В обработке(7), Получено сегодня(12), Требует внимания(1), Кодов за месяц(2,46 млн).
- Toolbar: поиск, статус, группа, дата, «Экспорт».
- Таблица: Заказ(link→detail drawer), Товар, Кол-во, Стоимость, Источник, Создан, Статус(badge), Прогресс(%), ⋮.
- Мастер заказа: 4 шага (Товары→Параметры→Финансы→Подтверждение) с расчётом «N × тариф = сумма, остаток после списания».

**Backend:** `GET /orders` + `POST /orders` (Idempotency-Key) + `GET /orders/:id`; статусы по ORD-026.

### 4.7 Vault (Code Vault)

- KPI-5: Всего(2 460 000), Свободно, Зарезервировано, Использовано, Выбыло.
- Actions: «Запустить сверку», «Выгрузить коды».
- Пулы (таблица: Пул, GTIN, Всего, Свободно, Резерв, Статус) + «Безопасность хранилища» (device: Envelope encryption).

**Backend:** `GET /api/codes` (маски), `GET /codes/:orderId/codes`, export `POST /codes/export`.

### 4.8 Labels (Конструктор этикеток)

- Toolbar: товар, шаблон (58×40), DPI (300), «История версий», badge «Автосохранение».
- 3 панели: **Palette** (элементы: Текст/Data Matrix/Штрихкод/Изображение/Линия/Переменное поле; данные товара), **Canvas** (этикетка 390×245 с DataMatrix), **Properties**.
- Actions: «Тестовая печать», «Сохранить версию».

**Backend:** `POST /labels/:codeKey/print` (PNG base64), `POST /labels/:codeKey/reprint` (AT-11), превью `<img data:image/png;base64>`.

### 4.9 Operations (Центр операций)

- Notice: «Выберите бизнес-операцию…».
- Grid 4 колонки op-card: Ввод в оборот, Приёмка, Отгрузка, Агрегация, Разагрегация, Перемещение, Списание, Возврат, Перемаркировка (+ др.).
- Каждая → мастер (4 шага: Основание→Коды→Проверка→Отправка).

**Backend:** `POST /import` (Ввод в оборот), `POST /withdrawal` (Списание/Вывод), WMS-операции — тикет 03.

### 4.10 Warehouse (Склад и ТСД)

- KPI-3: Текущая смена (оператор/место/начало/операций), Оборудование (сканер/принтер, статус), Качество смены (statbar).
- «Режим сканирования»: агрегация (прогресс N/4, список добавленных), кнопка завершить.

**Backend:** тикет 03 (WMS) — в MVP заглушка.

### 4.11 Documents (Документы)

- KPI-4: Черновики(42), Ожидают подписи(18), Ожидают контрагента(4), Завершено за месяц(312).
- Таблица: Документ(link), Тип(УПД/Акт), Операция, Контрагент, Кодов, Дата, Подпись(badge), Статус.

**Backend:** `GET /documents` (IMPORT|WITHDRAWAL|UTILISATION), `POST /import`, `POST /withdrawal`.

### 4.12 Reports (Отчёты)

- Grid report-card: Движение кодов, Агрегация, Остатки, Поступление, Реализация, Исключения и ошибки.
- Каждая: иконка, заголовок, описание, mini-chart SVG, «Открыть».

**Backend:** тикет 05 (1С-экспорт) + отчёты — эволюция; в MVP карточки-заглушки с данными API.

### 4.13 Billing (Биллинг)

- KPI-3: Доступный баланс (485 450 ₸), Расходы за июль (312 880 ₸), Лимит предупреждения (100 000 ₸).
- Таблица операций лицевого счёта: Дата, Операция, Основание, Сумма, Баланс, Статус.
- «Пополнить баланс» (drawer) — ref1c + сумма.
- Расходы по дням (chart).

**Backend:** `GET /billing/...`, `POST /billing/payments/import` (ref1c идемпотентно).

### 4.14 Integrations (Интеграции)

- Grid card: GS1 Kazakhstan, ИС МПТ, НКТ, 1С:ERP, WMS/оборудование, ЭДО/ЭЦП, Банк.
- Каждая: иконка, badge статус, описание, метрики (latency/очередь/ошибки), «Настроить».

**Backend:** порты `IGS1_ADAPTER`, `NKT_ADAPTER`, `MPT_ADAPTER`, `ECOM_ADAPTER` + метрики (эволюция).

### 4.15 Support (Поддержка)

- 2 колонки: список тикетов (круды, badge приоритет/статус) + чат (bubbles, input).
- SLA ответа, безопасный контекст (не раскрывать КМ).

**Backend:** SUP-055/056 — вне MVP; заглушка.

### 4.16 Organization (Организация и доступ)

- Tabs: Организация / Пользователи / Роли и права / Безопасность / Устройства.
- Организация: реквизиты (info-grid) + контроль подключения (statbar 100/100/83/92%).

**Backend:** tenant + пользователи + роли (тикет T0-RBAC) — частично.

### 4.17 Operator (Кабинет оператора)

### 4.18 Audit (Журнал аудита)
